# 0.20.0 发版审查 findings（`next` @ `ad56462a`，2026-09-26）

发版前对 `next` 最新提交 `ad56462a` 做的审查。它比 0.19.0（即当时的 `main`）多 157 个提交。每条发现都按四问（复现 / 基线对比 / 值不值得修 / 既往修复）作了裁决，处置已随 0.20.0 的发版分支 `release/0.20.0` 落地。

本表是原始清单与处置状态。「不修 / 暂不修」的终审条目收录进 [ReviewAdjudications.md](../Documentations/Internal/ReviewAdjudications.md)（A48–A51）。批次记录见 [ProjectEvolutionLog 第 60 节](../Documentations/Internal/ProjectEvolutionLog.md)。

## 审查做了什么

所有步骤都在 `git archive ad56462a` 导出的干净副本上做，只用远端依赖（没有 `USING_LOCAL_DEPENDENCIES`），用的是 agent 专属的 scratch 目录。

- **构建**：Xcode 26.6（CI 用的版本）下 `swift build -c release --arch arm64 / x86_64 --product swift-section` 都通过，0 warning、0 error；x86_64 版在 Rosetta 下能运行。Xcode 27（Swift 6.4，Swift Build 引擎）下 release 构建通过，只有发现 4 的两条 warning。发版流水线用的 Xcode 26.4.1 本机没有，这一点没有复现。
- **全量测试**：`swift test --skip IntegrationTests`（Xcode 26.6）共 2091 个测试，原始退出码 1。两条是已知的墙钟不稳定测试 `SharedCacheTests.differentKeysParallel…`，单独重跑通过；另外三条见发现 3。
- **Capstone v6 升级的端到端对比**：`6a324b87`（升级前）与 `ad56462a` 各编一个 release CLI，两边共用同一份 `Package.resolved`，只有 Capstone 不同。对宿主 macOS 27.0 cache 的 AppKit、SwiftUICore、SwiftUI 和 iOS 26.3.1 cache 的 SwiftUI 各出 `dump` 与 `interface`，8 对输出全部逐字节一致，耗时相差在 ±3% 以内。
- **Homebrew 配方的测试**：编一个只有 struct 的 dylib 再 `dump -s types`。最初记成「所有组合都通过」是错的：第一轮就崩过一次，我的检查脚本把 `$?` 放在命令替换之后展开，读到的是命令替换的退出码，把失败掩盖了。系统崩溃报告暴露了它，重测结果见发现 11。`--generate-completion-script` 生成 bash、zsh、fish 都正常。
- **代码审查**：由子 agent 审了最大的一批新代码（`_symbolic` 符号索引，`5cbf0378`），结论逐条复核；另外审了最新的 conformance 修复（`9a87a965`）和 Capstone v6 解码器改动（`9e6b93cf`）。
