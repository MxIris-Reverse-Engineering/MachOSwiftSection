# 0.15.1

A dependency-requirement release on top of `0.15.0`. No source changes: the only edit is how this package spells its requirement on MachOObjCSection, which had made the two packages impossible to co-resolve.

1. **`MachOObjCSection` is required as `0.8.104 ..< 0.9.0` instead of `exact: "0.8.102"`** — an exact requirement in a library deadlocks any consumer that also depends on MachOObjCSection directly.
2. **The lower bound moves to `0.8.104`**, picking up the ObjC relationship-table removal (`0.8.103`) and the synthesized-setter stripping fix (`0.8.104`).

Rendered output is byte-for-byte unchanged.

## Highlights

### Why `exact:` had to go

RuntimeViewer depends on this package *and* on MachOObjCSection directly, and pins the latter itself. Once it moved to `0.8.103` for the relationship-table removal, resolution stopped having a solution at all:

```
error: Dependencies could not be resolved because root depends on 'machoswiftsection' 0.15.0.
'machoswiftsection' 0.15.0 cannot be used because 'machoswiftsection' 0.15.0
depends on 'machoobjcsection' 0.8.102 and root depends on 'machoobjcsection' 0.8.103.
```

Two `exact:` requirements on one package have no intersection unless they name the same version, so this is unsolvable no matter how source-compatible the two releases are. Bumping the pinned version would only move the deadlock to the next release of either side; the requirement itself is what has to be a range.

The upper bound stays at the next minor rather than opening to `1.0.0`. MachOObjCSection's `0.8.103` removed public API from `ObjCIndexing` within the `0.8.x` line, so a wider bound would let a future minor float this package onto an incompatible indexer — the same failure mode `0.14.1` closed for `swift-demangling`.

This package does not use anything `0.8.103` removed: `ObjCClassReference`, the inheritance and protocol-adoption reverse tables, `subclasses(of:)` / `conformingClasses(toProtocol:)`, and `addSubIndexer` / `removeSubIndexer` on `ObjCInterfaceIndexer` have no callers here. The four files that reach into MachOObjCSection — `SwiftLayout/ObjCClassIndex.swift`, `SwiftLayout/ObjCProtocolIndex.swift`, `SwiftInspection/ClassHierarchyDumper.swift`, `TypeIndexing/ObjCInterfaceIndexer.swift` — build unchanged against `0.8.104`. `ConformanceProvider.subclasses(of:)` is this package's own protocol requirement and is unrelated.

## Compatibility

- No API additions, removals or renames. No snapshot `formatVersion` change.
- Consumers that pinned `MachOObjCSection` to `0.8.102` alongside this package must move to `0.8.104` or later; that is the point of the release.
- **Pinned dependencies** for this release — only the first line differs from `0.15.0`:
  - `MachOObjCSection` → `0.8.104 ..< 0.9.0`.
  - `MachOKit` → `exact: "0.52.100"`.
  - `MachOKitExtensions` → `from: "0.1.0"`.
  - `swift-semantic-string` → `from: "0.3.0"`.
  - `swift-demangling` → `0.4.5 ..< 0.5.0`, unchanged and for the reasons given in `0.14.1`.

## Requirements

- Swift 6.2+
- Xcode 26.0+ (CI validates the test matrix on Xcode 26.6 / macOS 26)
