## 摘要

给 interface / dump 输出补一个库侧的文件头部组件：Mach-O 元数据（install name、UUID、架构、文件类型、生成器版本）、library evolution 检测行（基于 dispatch thunk 计数）、以及「二进制不可恢复项」说明块（IUO 恒打印为 `?` 等）。头部做成公共组件，CLI 经 `printRoot` 接入（flag 门控，默认关），并导出给 RuntimeViewer 在 per-type 导出时自行调用。同时在 `SymbolIndexStore` 保留导出符号名集合，为无导出符号的成员输出 `// not exported` 标注（flag 门控）。

来源：[issue #106](https://github.com/MxIris-Reverse-Engineering/MachOSwiftSection/issues/106) 第 2、3、8 点。**开工前置条件：等 issue 第 6 点（`__C` 模块解析 + import 生成）的修复重构落地**，两者都动 `SwiftInterfaceBuilder` 的 `ImportsBlock` 一带。

## 动机

issue #106 三个互相咬合的痛点：

- **第 2 点**：`final` 一类推断是否有效取决于二进制是否开了 library evolution（非 resilient 模块根本不发射 dispatch thunk），但输出里没有任何一行告诉读者这件事。issue 实测四个二进制：只有 `Tj`（dispatch thunk）计数能区分 resilient 与否（`Tq` / `MV` 都不能 —— evolution 关闭的库仍有 317 个 `Tq`、5907 个 `MV`）。
- **第 3 点**：`SourceEditorGutter.updateLineNumberDisplay()` 带着 `// VTable offset: 66` 和 `// Address:`，看起来完全可调用，实际是 private、导出符号表零命中 —— issue 作者为它写了 stub 才发现。
- **第 8 点**：空白读起来像「原始代码就没有」而不是「二进制恢复不出来」。最典型的是 implicitly unwrapped optional：SE-0054 之后 `T!` 不是类型而是声明上的属性，mangling 与 reflection 里都不存在，`T!` 与 `T?` 的字段 type reference 被编译器完全去重。猜错无害（`?` 与 `!` ABI 相同），但读者应当被告知。

## 前期调研

调研基于 main（`32bf83c1`）；开工时须在 next 基线上复核（尤其 `SymbolIndexStore` —— 0001 号提案的 offset 化已在 next 落地，ingestion 循环形态可能漂移）。

- **这个库目前没有任何头部。** `SwiftInterfaceBuilder.printRoot()`（`Sources/SwiftInterface/SwiftInterfaceBuilder.swift:119-187`）第一行输出就是 `ImportsBlock`（`:121`）；CLI 两个命令都直接落盘（`Sources/swift-section/Commands/InterfaceCommand.swift:97-107`、`DumpCommand.swift:88-115`）。issue 里看到的 install name/UUID 头是 **RuntimeViewer 自己打的**，不是库的输出。且 RuntimeViewer 走 per-type 的 `printTypeDefinition`，绕过 `printRoot` —— 头部只挂 `printRoot` 的话 issue 作者实际用的导出形态反而看不到，所以必须做成可独立调用的公共组件。
- **`Tj` 计数今天就免费。** demangler 把 `Tj` 映射为 `.dispatchThunk`（swift-demangling `Demangler.swift:1611`），`SymbolIndexStore` 建索引时按 root node kind 分桶，`symbols(of: .dispatchThunk, in:)` 即得计数，零新增管线。注意语义边界：`Tj == 0` 不严格等于「未开 evolution」（一个没有任何可派发 public 成员的 resilient 模块也可能为 0），措辞用「detected / not detected」而非断言。
- **导出符号集读过但没保留。** `SymbolIndexStore.buildStorageImpl` 的第二遍循环遍历 `machO.exportedSymbols`（export trie，main 基线 `SymbolIndexStore.swift:234-243`），但只补 symtab 缺的名字、集合本身不落 `Storage`；`Symbol.isExternal` 是「未定义导入」判据而非「已导出」判据，易误读。`nlist` 的 `.ext` 位是更弱的信号（`N_PEXT` 私有外部也置位），authoritative 来源是 export trie。**构建导出集必须无条件遍历 `exportedSymbols`**，不能用现有循环里过了 `symbolByName == nil` 筛的残余。
- **标注发射点现成。** interface 路径地址注释集中在 `renderMember`（`Sources/SwiftPrinting/SwiftDeclarationPrinter.swift:376-410`，`AddressComment` 于 388/395/403，成员符号的 mangled name 就在手边）；dump 路径经 `DeclarationRenderConfiguration.memberAddressComment`（`Sources/SwiftDeclarationRendering/DeclarationRenderConfiguration.swift:100-111`）分布在六处 Dumper。
- **不可恢复项列表大半已成文。** `Roadmaps/2026-04-13-swiftinterface-dump-improvements.md:664` 起的「Known limitations (binary metadata cannot recover)」已有 11 条（IUO、`@frozen`、class 级 `@MainActor`、`indirect enum`、`open` vs `public` 等）；issue 追加的参数内部名、`@available`、`@discardableResult`、默认参数值、`internal`/`fileprivate` 之别尚未在列。
- **头部元数据来源**（MachOKit sibling 查证）：install name 即 `MachOFile.imagePath`（`LC_ID_DYLIB`）；UUID 不在 `MachORepresentable` 上，需 `loadCommands` → `.uuid` → `UUIDCommand.uuid`；cpu / fileType 走 `machO.header`（`Sources/swift-section/Utilities/Extensions.swift:54` 已有用例）；生成器版本取 `Version.swift`。MCP 的 `describeBinary`（`MCP/Sources/swift-section-mcp/BinarySession.swift:88-94`）是字段清单的现成先例。
- **快照字节稳定性约束**：头部若含日期会破坏快照/基线的可复现性 —— 日期做成可选参数，测试与默认 CLI 输出不含。

## 提议方案

1. **`SymbolIndexStore` 导出集**：`Storage` 增加导出名 `Set<String>`（无条件从 `machO.exportedSymbols` 构建），公开 `isExported(name:in:)` 查询。
2. **头部公共组件**：新 semantic 组件（暂名 `InterfaceHeaderBlock`，落在 `SwiftPrinting`），输入为一个纯值的 `InterfaceHeaderInfo`（install name / UUID / arch / fileType / 生成器版本 / 可选日期 / dispatch thunk 计数 / 是否附不可恢复项说明），由库提供从 `MachORepresentableWithCache` 构建它的工厂。渲染为注释块，形如：

   ```
   // Generated by swift-section <version>
   // Image: /path/to/SourceEditor (arm64e, dylib)
   // UUID: XXXXXXXX-…
   // Library evolution: detected (2216 dispatch thunks)
   // Not recoverable from the binary (omitted, not absent):
   //   IUO (`T!`) always prints as `T?` (ABI-identical) · parameter internal names ·
   //   @available · @discardableResult · default argument values · internal vs fileprivate · …
   ```

3. **CLI 接线**：`printRoot` 在 `ImportsBlock` 前按新 flag（暂名 `--emit-header`，默认关）输出头部；`dump` 命令同 flag 在输出前拼接。RuntimeViewer 的采用是后续在其仓库接线（公共组件已就绪即可）。
4. **`// not exported` 标注**：新 flag（暂名 `--emit-export-status`，默认关）门控；interface 的 `renderMember` 与 dump 的 `memberAddressComment` 兄弟组件处，成员符号名不在导出集时输出。语义注意：标注含义是「该成员没有任何导出符号」，对 stripped 二进制/dyld cache 镜像按 export trie 事实输出，不做访问级别猜测。

### 非目标

- 不猜测访问级别（`private` / `internal` / `fileprivate` 不可恢复，只标「not exported」这个符号表事实）。
- 不断言 `Tj == 0` 即未开 library evolution（措辞留有余地）。
- 不在本提案里动 RuntimeViewer（组件导出后由其自行采用）。
- 不把 Roadmaps 的 11 条限制全文塞进头部（头部是短清单，全文以链接/文档承载）。

## 详细设计

```swift
// SwiftPrinting（示意）
public struct InterfaceHeaderInfo: Sendable {
    public var generatorVersion: String
    public var imagePath: String?
    public var uuid: UUID?
    public var cpuDescription: String?
    public var fileTypeDescription: String?
    public var generatedDate: Date?          // nil ⇒ 不打印日期行（快照稳定）
    public var dispatchThunkCount: Int?
    public var includesUnrecoverableNotes: Bool
}

// MachOSymbols（示意）
extension SymbolIndexStore {
    public func isExported(name: String, in machO: MachO) -> Bool
}
```

`dispatchThunkCount` 由调用方从 `symbolIndexStore.symbols(of: .dispatchThunk, in: machO).count` 填入；`SwiftInterfaceBuilder` 本就持有 `machO`。`isExported` 查询的键是 mangled name（`FunctionDefinition.symbol` / `Accessor.symbol` 携带，`renderMember` 处直接可得）。

## 替代方案考量

- **头部仅由 CLI 拼接、库不提供组件** —— 否（用户决策）。RuntimeViewer 的 per-type 导出（issue 实际场景）将永远得不到 evolution 行与不可恢复项说明。
- **头部默认开** —— 否（用户决策：注释类信息挂 flag）。默认输出保持字节不变。
- **用 `nlist` 的 `.ext` 位判导出** —— 否。`N_PEXT` 私有外部会误报，export trie 是 authoritative 来源，且已有现成遍历点。
- **`// not exported` 换成访问级别猜测（如 `// private?`）** —— 否。访问级别不可恢复，猜测违反「诚实标注」原则（见渲染注释可读性约定）；符号表事实是能给的最强陈述。

## 影响

### 源码兼容性（source compatibility）

全部纯新增：`SymbolIndexStore.isExported`、`InterfaceHeaderInfo` / `InterfaceHeaderBlock`、两个 CLI flag、`SwiftDeclarationPrintConfiguration` / `DeclarationRenderConfiguration` 新开关（带默认值 false）。默认输出字节不变（两个 flag 默认关）。

### ABI 兼容性（条件项）

不适用 —— 本库以 SPM 源码分发，使用方每次重新编译。

### 下游影响

本仓库内：`MachOSymbols`（导出集，注意 `SymbolIndexStore` 是进程级共享缓存，`Storage` 增量要评估内存 —— 0001 号提案的 offset 化已在 next 落地，导出集应优先存字符串表引用而非驻留字符串，实现时对齐该形态）、`SwiftPrinting`、`SwiftDeclarationRendering`、`SwiftInterface`、`swift-section`。

下游仓库：RuntimeViewer 可择期采用头部组件替换自制头（正向，非强制）。

### 文档与示例

README 的 CLI 选项段、AGENTS.md、`Roadmaps/2026-04-13-swiftinterface-dump-improvements.md` 的 Known limitations 补齐 issue 追加项并与头部短清单互链；头部字段与措辞属于「从 API 签名看不出来的契约」，预计要一篇使用指南或并入现有 CLI 文档。
