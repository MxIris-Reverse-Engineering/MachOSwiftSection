摘要

新增一个公开的格式化值类型 MultilineTypeFormatting（SwiftDeclarationRendering），把已经打印好的 Swift 源码（SemanticString）里放不下的类型按括号拆成多行：一个类型一行放得下就不动；放不下时，整个类型照 TypeAliasFormatter 的结构规则拆开——有两个及以上参数的泛型参数列表每个参数一行，单参数泛型、元组、函数类型与声明的参数列表、[…] 集合语法糖只在里面有拆开的部分时才拆。它只插入换行和缩进，文字、semantic type、identifier 和各种 region 原样保留。

swift-section dump / interface 新增 --multiline-types 与 --maximum-line-width，InterfaceRequest / DumpRequest 新增同名字段；默认关闭，关闭时输出逐字节不变。RuntimeViewer 在拿到一个定义的完整打印之后调用一次即可，打印器本身一行不改。

没问你、自己定的（可推翻）

  • 默认宽度 100 列（swift-format 的默认值），行首缩进不计入。
  • CLI 参数名 --multiline-types 与 --maximum-line-width；只给宽度不给开关算用法错误。
  • diff、evolution、snapshot 与 ObjC 输出不接。
  • RuntimeViewer 的开关与调用留给它自己的后续改动。

方案

  1. 一行的内容宽度不超过 maximumLineWidth 就原样保留。内容宽度是这一行的字符数减去行首缩进，所以拆不拆与嵌套深度无关，嵌套定义的契约自然成立。
  2. 超宽的行解析成括号树。只在 .standard 类型的 atom 里找括号；字符串字面量、反引号标识符、// 之后的内容是文字；-> 不是括号。括号不配对就整行原样保留。
  3. 找出放不下的类型。不在其它泛型参数列表里面的泛型参数列表算作一个类型的最外层；它的 > 落在第 maximumLineWidth 列之后，这个类型就算放不下。
  4. 放不下的类型按结构规则拆。有两个及以上参数的泛型参数列表一律每个参数一行；单参数泛型、元组、函数类型的参数列表、[…] 只在某个元素已是多行时才拆。
  5. 外层括号跟着拆。函数声明的参数列表、enum case payload、元组、泛型参数子句、attribute 参数，只在某个元素已是多行时才拆。
  6. 拆开的列表这样排。开括号留在原行末尾；参数另起一行，缩进为行首缩进加 4 个空格乘以嵌套层数；, 变成 ,；闭括号另起一行回到上一层。

做不到的

SwiftUI 的 ModifiedContent 链向左嵌套，二十多层 modifier 拆开后第一个参数仍会缩进二十多层；压平这种链要按语义改写类型，不属于排版，本提案不做。

非目标

  • 不改打印器；默认关闭时所有输出逐字节不变，fixture baseline 与渲染 A/B 不受影响。
  • diff、evolution、snapshot 不接（按行标记增删、JSON）；ObjC 输出不接。
  • 不单独按行宽拆长参数列表；参数列表只在某个参数的类型被拆开时随之拆开。
  • 不做 TypeAliasFormatter 的单参数泛型展开、其它缩进宽度与图形视图。
  • RuntimeViewer 的设置界面与接入不在本提案里实现。

打印器照旧输出一行一个声明；调用方在交出产物前调用一次 format(_:)。三个文件都是 MultilineTypeFormatting 的 internal 扩展。

format(source)
└── for each line (atoms split at "\n" keep type + identifier)
    ├── content width (minus leading indentation) <= maximumLineWidth ──► copy unchanged
    └── BracketTree(line)          (.standard atoms only; strings, backticks, "//", "->" are text)
        ├── nil (unbalanced) ──► copy unchanged
        └── Layout
            ├── outermost generic argument list whose ">" lies past the width ──► long type
            ├── inside a long type: generic argument list with >= 2 arguments ──► break
            ├── any list with a multi-line element ──► break        (bottom-up)
            └── emit "<" "\n" indent(L + 4k) element "," "\n" … "\n" indent(L + 4(k - 1)) ">"

详细设计

公开 API 
public struct MultilineTypeFormatting: Hashable, Sendable {
    /// The widest a line's content may be, in characters; indentation does not count.
    public var maximumLineWidth: Int

    /// - Precondition: `maximumLineWidth > 0`.
    public init(maximumLineWidth: Int = 100)

    /// `source` with its long types laid out over several lines.
    public func format(_ source: SemanticString) -> SemanticString
}

extension InterfaceRequest {
    public var multilineTypeFormatting: MultilineTypeFormatting?
}

extension DumpRequest {
    public var multilineTypeFormatting: MultilineTypeFormatting?
}
--multiline-types              Break a type that runs past the line width over several lines, at its brackets.
--maximum-line-width <columns> The widest a line may be, not counting its indentation, before
                               --multiline-types breaks its types. (default: 100)
行与宽度
  • 先把 source.components 按 \n 切成行；含 \n 的 atom 在 \n 处切开，各段保留原 type 与 identifier。
  • 行首缩进 L 是行首连续空格数（跨 atom 计）；内容宽度是这一行的 Character 数减去 L。
  • 内容宽度不超的行原样复制，不解析。
  • 行之间互不影响；括号跨行的输入每行单独看都不配对，因此原样保留——这就是幂等的原因。
括号树
  • 只有 .standard atom 参与扫描；类型名、声明名（含 interface 里的运算符名）、注释等 atom 整体是文字。
  • " 与反引号之间是文字；// 之后到行末是文字；-> 是箭头；深度大于 0 时的 , 分隔元素。
  • < 前面（跳过空白）的 atom 是 .type(_, .declaration)、.function(.declaration) 或 .member(.declaration) 时，这个列表是泛型参数子句，否则是泛型参数列表。
  • 括号不配对或未关闭返回 nil，整行原样保留；dump 里的 static func < infix(…) 就走这条路。
排版与生成
  • 不在任何泛型参数列表里面的泛型参数列表，> 的内容列号大于 maximumLineWidth 时，标为长类型的根。
  • 自下而上：长类型内部元素数不少于 2 的泛型参数列表拆；任何列表有元素是多行时拆；其余不拆。
  • 拆开的列表：开括号后插入 \n 与 L + 4k 个空格；, 换成 , 再插入换行与缩进；闭括号前插入 \n 与 L + 4(k − 1) 个空格。
  • 插入的 atom 都是 .standard，identifier 取前一个括号或逗号 atom 的 identifier，region 不会被切断。
  • 空列表 () 从不拆。
保持性承诺
  1. 内容宽度不超的行逐 atom 不变。
  2. 去掉插入的换行与缩进、把 , 还原成 , ，得到与输入相同的文字。
  3. 每个原有字符所在 atom 的 semantic type 与 identifier 不变；冻结后各种 region 分离结果不变。
  4. 幂等：format(format(x)) == format(x)。
  5. 与缩进可交换，由此嵌套定义的契约在格式化后仍成立。

调研

七条查证过的事实
  • 两套打印器。interface 走 SwiftPrinting（BoundGenericNodePrintable.swift:66 写 <、, 、>），dump 走上游 swift-demangling 的 NodePrinter（经 DemangleResolver.swift:31）。两边的括号与逗号都是 .standard 的独立 atom。
  • typealias Body 一行。renderMergedAssociatedTypeRecords（SwiftDeclarationPrinter+Headers.swift:305）把整个类型接在 typealias X = 后面同一行。
  • region 编码在 identifier 上。插入不带编码的 atom 会把同一个 region 切成两个。
  • 嵌套定义契约。removingIndentation(levels:) 按字节删每行开头 levels * 4 个空格；拆不拆不能取决于缩进深度。
  • 运算符。上游把 infixOperator 写成 "< infix" 这种 .standard atom（NodePrinter.swift:499）。
  • 调用方的出口。RuntimeViewer 拼好 newInterfaceString 后缓存（RuntimeSwiftSection.swift:364），已依赖 SwiftDeclarationRendering；InterfaceRequest.swift:225 的 printRoot()；DumpRequest.swift:513 的 DumpSession.dump。
  • TypeAliasFormatter 的规则。多参数 < 一律展开；单参数、(、[ 只在子元素多行时展开；-> 不算括号。仓库没有 license 文件，只借用规则、不复制代码。

替代方案

六条被否的路径
  • 纯按行宽逐层决定。同一个类型在不同深度排版不同；用户否掉。
  • 完全照 TypeAliasFormatter、不看行宽。每个 Swift.Result<Swift.Int, Swift.Error> 都被拆成四行；用户否掉。
  • 在打印器里写换行或断点标记。两套打印器要各改一遍，上游 NodePrinterTarget 要加要求并发版；memoize 的片段会带上依赖列号的决定。
  • 做成打印配置项、由每个公开入口格式化。二十来个公开入口互相调用，要么重复格式化要么拆分每个入口；dump 还要另接。
  • 在纯文本上格式化。丢掉 semantic type、identifier 与 region。
  • 扫描所有 atom 的所有字符。运算符名、私有类型名 (Visitor in $…) 也含括号。

影响

  • 源码兼容性：纯新增；新字段与 init 参数默认 nil。
  • ABI：不适用，SPM 源码分发。
  • RuntimeViewer（后续）：设置里加开关，在 RuntimeSwiftSection.swift:364 缓存前调用 format，开关变化时清 interfaceByObject 缓存；不必改依赖。
  • 文档：agent 插件 skill、SwiftSectionKit 调用方指南与模块参考、CLAUDE.md 模块清单；发版时写 changelog。
  • API 演进：以后的选项（单参数展开、缩进宽度）作为带默认值的属性加进 struct。
