摘要

Tests/IntegrationTests/ 里有四套演进（evolution）的维护者手检套件：Swift 的时间线报告、Swift 带标注的联合接口、ObjC 的时间线报告、ObjC 带标注的联合头文件，分在三个文件里，一共 21 个套件类、43 个测试。它们读的是同几条版本轴（哪几份 dyld cache、哪几个镜像），却各自把轴再定义一遍、互相引用对方的类属性，四条管线各自又把「单镜像」与「镜像组」写成两条几乎一样的路径。

本提案把它们合成一套：新目录 Tests/IntegrationTests/Evolution/ 下，版本轴只定义一次（一个轴一个套件类，共 10 个），轴按管线读的元数据（__swift5_* 或 __objc_*）各自筛出版本；四条管线收进一个协议，每条只写一遍，镜像组与单镜像在管线里用一个开关分开。每种输出在轴上仍是一对显式的一行测试（写文件 / 打到控制台），原有的 43 个「轴 × 输出」组合一个不增不减，输出文件名不变，只改测试名。只动 IntegrationTests，不碰库代码。

要你定

已批准并落地。以下是没问用户就采用的假设：

  1. 默认三版本轴上 Swift 一侧沿用实际读的 SwiftUI、ObjC 一侧沿用 AppKit，拆成两个轴套件，不借合并之机统一成 AppKit；过时的「AppKit」注释改正。
  2. 只保留现有的「轴 × 输出」组合，不顺手给轴补别的管线；要补时只是在套件里加一对一行测试。
  3. 测试名改变（例如 ABIEvolutionTestSuite.DyldCacheTests/evolutionFile() → EvolutionTestSuite.SwiftUIDyldCacheTests/swiftReportFile()），旧名字不留别名——没有脚本按名字调用它们（已 grep 过 Scripts/ 与 .github/）。

提议方案

在 Tests/IntegrationTests/Evolution/ 下用三个文件取代现在的三个演进文件：

  1. EvolutionAxis.swift：版本轴只定义一次。EvolutionMetadataLanguage 判镜像带不带管线要读的元数据；EvolutionAvailabilityPlatform 记要标的平台，两种语言各有拼法；EvolutionImage / EvolutionVersion / EvolutionAxis 取代嵌套元组。基类 MultiVersionDyldCacheImageTests 挪到这里：每份 cache 打开一次，把套件列出的镜像里 cache 有的都收下，只要有主镜像就保留这份 cache；再为两种语言各算一条轴存下——主镜像被筛掉的版本不上这条轴。默认三版本 cache 与 51 份归档 cache 的清单作为基类的两个 static 属性。
  2. EvolutionDumpTests.swift：四条管线各写一遍。协议只要求 evolutionAxis(for:)；dump(_:to:) 是唯一入口，跑管线得到 EvolutionDumpOutput，再打到控制台或写文件，文件一律按最新版本的镜像组命名。每条管线内部按 axis.comparesImageGroups 选单镜像或镜像组的构建器入口。
  3. EvolutionTests.swift：十个轴套件，挂在 enum EvolutionTestSuite 下，每种输出一对一行测试（<种类>File / <种类>String）。
  4. SwiftInterfaceTestSupport.swift：write(_:forImageGroup:) 改收 [EvolutionImage]。

非目标

  • 不合并 diff 套件（SwiftDiffableInterfaceBuilderTestSuite）的两版本基类，也不改它读 cache 的方式；SwiftUICoreSimulatorTests 继续借用它的 CrossVersionMachOFileTests。
  • 不动 SwiftInterfaceBuilderTests.swift（单镜像接口套件；工作区里有维护者未提交的改动）、MachOSymbols 里的重复，以及其它不属于演进的 IntegrationTests。
  • 不改任何库代码、不改 CLI，也不新增 Package.swift 依赖。
  • 不运行 IntegrationTests；输出比对由维护者手动做。

详细设计

EvolutionAxis.swift 
enum EvolutionMetadataLanguage: Sendable {
    case swift   // __swift5_* sections
    case objc    // __objc_* sections

    func isCarried(by machOFile: MachOFile) -> Bool
}

enum EvolutionAvailabilityPlatform: Sendable {
    case macOS
    var swiftSpelling: String { "macOS" }   // @available(macOS, …)
    var objcSpelling: String { "macos" }    // API_AVAILABLE(macos(…))
}

struct EvolutionImage: Sendable { let imageName: String; let machOFile: MachOFile }

struct EvolutionVersion: Sendable {
    let label: String
    let images: [EvolutionImage]            // the primary image first
    var primaryImage: EvolutionImage { images[0] }
}

struct EvolutionAxis: Sendable {
    let versions: [EvolutionVersion]
    let comparesImageGroups: Bool
    let availabilityPlatform: EvolutionAvailabilityPlatform?
}

@TestActor
class MultiVersionDyldCacheImageTests: Sendable {
    let caches: [FullDyldCache]
    private let axesByLanguage: [EvolutionMetadataLanguage: EvolutionAxis]

    class var cachePaths: [DyldSharedCachePath] { defaultMacOSCachePaths }
    class var cacheImageName: MachOImageName { .SwiftUI }
    class var cacheImageNames: [MachOImageName] { [cacheImageName] }
    class var availabilityPlatform: EvolutionAvailabilityPlatform? { nil }

    static var defaultMacOSCachePaths: [DyldSharedCachePath] { [.macOS_15_5, .macOS_26_5_2, .macOS_27_0] }
    static var archivedMacOSCachePaths: [DyldSharedCachePath] { /* 51 versions, 11.0.1 → 11.0, 12.0.1 → 12.0 */ }

    init() async throws
    nonisolated func evolutionAxis(for language: EvolutionMetadataLanguage) -> EvolutionAxis
}

axesByLanguage 在 init 里算好、以 let 存下：类属性是 @TestActor 隔离的，nonisolated 的协议实现读不到它们，读一个 Sendable 的 let 则可以。实现时若字典的强制解包不合适，改成两个 let 加一个 switch。

EvolutionDumpTests.swift 
enum EvolutionDumpKind: Sendable {
    case swiftReport      // swift-section evolution: -Evolution.txt / .json
    case swiftInterface   // evolution --interface: -EvolutionInterface.swiftinterface
    case objcReport       // objc evolution: -ObjCEvolution.txt / .json
    case objcInterface    // objc evolution --interface: -ObjCEvolutionInterface.h
    var language: EvolutionMetadataLanguage
}

enum EvolutionDumpDestination: Sendable { case console, file }

struct EvolutionDumpOutput {
    let suffix: String
    let text: String
    let textFileExtension: String
    let json: String?     // nil for an interface
}

protocol EvolutionDumpTests: SwiftInterfaceDumpTests {
    func evolutionAxis(for language: EvolutionMetadataLanguage) -> EvolutionAxis
}

@available(macOS 13.0, iOS 16.0, tvOS 16.0, watchOS 9.0, *)
extension EvolutionDumpTests {
    var indexConfiguration: SwiftDeclarationIndexConfiguration { .init(showCImportedTypes: false) }

    func dump(_ kind: EvolutionDumpKind, to destination: EvolutionDumpDestination) async throws

    private func swiftReport(over axis: EvolutionAxis) async throws -> EvolutionDumpOutput
    private func swiftInterface(over axis: EvolutionAxis) async throws -> EvolutionDumpOutput
    private func objcReport(over axis: EvolutionAxis) async throws -> EvolutionDumpOutput
    private func objcInterface(over axis: EvolutionAxis) async throws -> EvolutionDumpOutput

    private func swiftSnapshotDocument(of image: EvolutionImage, label: String) async throws -> ABISnapshotDocument
    private func objcSnapshotDocument(of image: EvolutionImage, label: String) async throws -> ObjCAPISnapshotDocument
}
  • swiftReport：measuringPreparation 里对每个版本的每个镜像取快照；镜像组配成 ABIImageSnapshot 交给 evolution(ofImageGroups:versions:)，单镜像交给 evolution(of:)，两版本时追加 ABIDiffer 对照行；JSON 用同一个 ABIEvolution 编码。
  • swiftInterface：按开关选 AnySwiftEvolutionInterfaceBuilder 的 imageGroups: 或 versions: 构造器，平台传 swiftSpelling；正文末尾加 // ABI-breaking on this axis: 行。
  • objcReport：同 swiftReport，换成 ObjC 的快照、构建器、differ 与 JSON 编码器；对照行写 API-breaking。
  • objcInterface：逐版本 addVersion(images:version:) 或 addVersion(indexer:machO:version:)，build(availabilityPlatform:) 传 objcSpelling；正文末尾加 // API-breaking on this axis: 行。

SwiftUIDyldCacheTests 另保留 swiftInterfaceStringViaPackFacade（@available(macOS 14.0, …)），从 Swift 轴取三个主镜像交给 SwiftEvolutionInterfaceBuilder，照旧不包 measuringPreparation（@TestActor 上的测试把隔离的闭包交出去会触发 region isolation 检查）。

与现状的行为差异
  • 测试名全部改变，套件从四个 enum 合到 EvolutionTestSuite 一个下。
  • 空轴：现状的 file 入口在轴上一个版本都没有时静默返回，string 入口抛 fewerThanTwoVersions；合并后两种都抛。只在 cache 卷没挂载、镜像全不在时出现。
  • 保留的 cache：现状只留「主镜像在这条语言的轴上」的 cache，合并后留「有主镜像」的 cache。在这十条轴上结果相同。
  • 输出内容与文件名不变；JSON 里的 createdAt 每次运行本来就不同。

动机

五处具体的重复
  1. 同一条轴定义了四次。SwiftUI 加 SwiftUICore 在默认三版本 cache 上的轴，在 ABIEvolutionTests.swift:239、SwiftEvolutionInterfaceBuilderTests.swift:286、ObjCAPIEvolutionTests.swift:244 与 :460 各写一次；51 份归档 cache 上同样四次。AppKit 组的两条轴、AppKit 单镜像的两条轴在 ObjC 两组里各写两次。
  2. 轴靠互相引用来对齐。51 份归档 cache 的版本列表只在 SwiftEvolutionInterfaceBuilderTestSuite.ArchivedDyldCacheTests.cacheVersions 里，ObjC 两组和 Swift 报告那组都去引用这个 Swift 接口套件的类属性。
  3. ObjC 的轴是继承 Swift 的轴再改一处。ObjCAPIEvolutionTestSuite.MultiVersionDyldCacheImageTests 只为覆写 isOnAxis(_:)，把 __swift5_* 换成 __objc_*。
  4. 每条管线把单镜像与镜像组写成两遍，四条管线合计 16 个入口、8 个准备函数；indexConfiguration 在两个协议扩展里各写一份。
  5. 注释已经和代码对不上。两个 Swift 侧的 DyldCacheTests 注释写着读 AppKit，实际继承基类默认的 .SwiftUI；ObjC 的同名套件确实读 AppKit。

调研

八条查证过的事实
  1. 四条管线的输入与差异：Swift 报告与 ObjC 报告都是「每个镜像索引 → 冻结成快照 → 经 JSON 往返 → 时间线」，单镜像两版本时与 differ 对照；Swift 接口用 AnySwiftEvolutionInterfaceBuilder，ObjC 头文件用 ObjCEvolutionInterfaceBuilder，末尾各加一行结论。
  2. 单镜像与镜像组的输出不同，不能一律走镜像组：ABIEvolutionBuilder.evolution(ofImageGroups:versions:)（Sources/Output/SwiftDiffing/ABIEvolutionBuilder.swift:51-62）给版本描述写 imageNames，evolution(of:)（:16-27）带 provenance；AnySwiftEvolutionInterfaceBuilder.prepare（:189-194）与 ObjCEvolutionInterfaceBuilder.swift:269-275 也按版本形态二选一。
  3. 文件命名在单镜像时两种写法相同（SwiftInterfaceTestSupport.swift:43-71），合并后一律用镜像组的写法。
  4. 可用性平台两种语言拼法不同：Swift 传 "macOS"，ObjC 传 "macos"；只有归档轴的两种「接口」管线传平台。
  5. Swift Testing 不继承测试：每个轴套件仍要自己声明测试，能省的是测试体和轴的重复定义。
  6. 为什么不用参数化测试：一点就跑完全部参数，51 版归档轴要几个小时。
  7. IntegrationTests 不让 agent 运行，只能验证编译；CI 的 swift test 会编译 IntegrationTests，且用 Xcode 26.6，所以 26.6 也要编一遍。
  8. 目录无需登记：目标用默认路径 Tests/IntegrationTests，新子目录自动收进来；Tuist 按目标名映射。

替代方案

五条被否的路径
  • 参数化测试：一点就跑全部管线，没法在跑之前单独挑一种输出。用户选了显式测试。
  • 所有轴都走镜像组路径：版本描述与 JSON 会变，和 CLI 单镜像的输出也不一致。
  • 把默认三版本轴统一成 AppKit：Swift 一侧的输出会变，维护者手里正在比的结果对不上。
  • 轴做成值、套件按轴参数化：同参数化测试的问题，Xcode 里也看不到按轴分开的套件。
  • 只抽公共函数、保留四个 enum：轴的四重定义和互相引用还在，没解决「Swift 和 ObjC 各有一套」。

影响

  • 源码兼容性：纯测试改动，不涉及任何公开 API。
  • ABI 兼容性：不适用 —— 本库以 SPM 源码分发，本提案也只改测试目标。
  • 下游：只有 IntegrationTests 目标受影响；下游仓库不依赖它。
  • 文档：ABIEvolutionDesign.md:235-243 改成新路径与套件名；账本、任务报告与已落地提案里的旧名字是历史记录，不改。
  • API 演进与废弃：不适用；旧测试名直接删除，不留别名。
