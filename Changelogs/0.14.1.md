# 0.14.1

A patch release on top of `0.14.0`. No new subsystems: this one closes the regressions the SwiftDump leaf migration left behind, and opens the comment-templating mechanism — already complete library-side — to the command line.

1. **The comment-template mechanism is reachable from the CLI** — `dump` and `interface` both accept a `Transformer` configuration in three layers (a RuntimeViewer-shaped JSON file, a whole-module enum-layout preset, per-module templates), and a new `swift-section transformer` subcommand documents the tokens and built-in templates.
2. **Specialized definitions render bound again** — since `0.12.0-beta.6` a user-driven specialization printed an unbound header (`Box<A> where A: …`) with unsubstituted field types; only the layout comments reflected the specialization. The runtime substitution machinery is back on the interface path.
3. **The interface path's error contract is restored** — field-record reads, metadata comments and type printing propagate errors again instead of being swallowed into ghost blank lines, the multi-payload enum descriptor cache is back, and a `Void`-payload enum case is spelled `case a()` on both the dump and interface paths.
4. **Accessor-function (kind-9) symbolic references print honestly** — they used to render as an empty string, so the enum-case payload gating closed parentheses around nothing and emitted invalid Swift (`case type()`). The bug predates the leaf migration.
5. **CI runs debug and release in parallel on Xcode 26.6** — with the per-configuration SwiftPM build directory cached, a cold run now costs roughly what the release leg alone used to.

Default output is byte-for-byte unchanged unless you pass one of the new template options.

## Highlights

### `swift-section` — templating the rendered comments

- `TransformerOptionGroup` (shared by `dump` / `interface` / `transformer config`) exposes the mechanism in three layers, each overriding the previous: `--transformer-config <json>` (decoded straight into `Transformer.SwiftConfiguration`, so a RuntimeViewer-persisted configuration replays verbatim) → `--enum-layout-style <preset>` → per-module template / hexadecimal options (8 template slots across the five Swift comment modules).
- A template value containing `${` is literal; otherwise it names a built-in template, matched case/space/hyphen/underscore-insensitively. **An unknown name is a `ValidationError`, not a literal** — a template with no placeholder renders a constant comment, which is never what a misspelled name meant to produce.
- **An enabled module turns on the comment kind it renders.** Previously `--enum-layout-style compact` without `--emit-enum-layout` produced nothing, with no hint why. The reverse does not hold: `--emit-field-offsets` alone still uses the built-in rendering (the byte-for-byte equivalent of the `detailed` preset). The merge is an OR, so an explicit `--emit-…` is never turned back off by a disabled module.
- New `swift-section transformer` subcommand for discovery: `tokens` (per-module `${token}` lists, enum layout split by strategy line / case / fixed byte), `templates` (built-in named templates and their expansions), `config` (freeze a set of options into JSON, reusing the same option group).
- `interface` gains `--emit-type-layout` / `--emit-enum-layout` — its print configuration always had the fields and builds the static layout provider on demand; only the CLI never surfaced them.
- With no template option the option group yields `nil` and callers leave their render configuration untouched.

### `SwiftPrinting` — bound rendering for specialized definitions

- `BoundDumpedTypeNameRenderer` moves down to `SwiftDeclarationRendering` verbatim (`TypedDumper` keeps forwarding, so the dump path is unchanged), and the new `SpecializedMetadataNodeSubstitution` mirrors the old `resolveFieldMetatype` / `boundDumpedTypeNode` runtime resolution on `MetadataWrapper`.
- A specialized definition (`TypeDefinition.isSpecialized`) now prints the concrete-argument header (`Box<Int>`, generic-signature clause skipped, invertible markers and superclass kept) and substitutes each field's type node through the specialized runtime metadata, falling back per field to the unbound node.
- Runtime-driven substitution was restored rather than replaced with static node substitution: a dependent member such as `A.RawValue` is resolved by the runtime through the witness table to its final concrete type, which a syntactic rewrite cannot do.

### Leaf-migration regression fixes

All seven surviving findings from the audit of the SwiftDump leaf migration, with the hard requirement that post-refactor behavior match the pre-refactor commit:

- `MultiPayloadEnumDescriptorCache` is back in `SwiftDeclarationRendering` as a per-image **partial** map shared by dump and interface — one bad descriptor degrades only its own enum, and the per-enum linear rescan of `__swift5_mpenum` is gone.
- `storedFieldComments` / `enumCaseComments` / `renderModelFields` are `throws` again. No swallowed errors, no ghost blank indented lines, no stray blank line on the type-layout error path.
- Enum-case payload presence follows the field record's mangled type name (captured at index time as `FieldFlags.hasMangledTypeName`, so rendering never re-reads the record positionally). A `Void` payload prints `case a()` — it is a real payload case in the ABI — exactly like the dump path.
- Extension conformance-clause collapse semantics are restored: a `nil` protocol node keeps the clause with an empty name; only a thrown resolution error drops it together with its `@retroactive` / global-actor markers.
- The nested field-offset depth-limit `#log` diagnostic is back (same subsystem / category strings as before the module split), and SwiftDump's dead copies (the depth-limit constant, `mergedRecords` / `collectUniqueRecords`) are deleted.
- The diff renderer's `printField` / `printEnumCase` keep their own per-member-catch, rendered-text-gating contract — that is their original design, needed for standalone `+`/`-` members.

Verified by a cross-commit differential harness (dump + interface over the fixture framework plus a purpose-built edge-case dylib, pre-refactor tree vs fixed tree): the edge corpus converges to zero diff, and every remaining fixture difference traces to a deliberate change already shipped in an earlier release (SE-0452 integer-argument printing, enum-layout comment wording).

### Accessor-function references

- `SwiftPrinting`'s node printers had no case for `Node.Kind.accessorFunctionReference` — the kind-9 symbolic reference the compiler embeds when the deployment target's runtime cannot demangle a type's mangling, or when a field type is always-noncopyable (its reflection metadata is gated behind a runtime capability check). It now renders as `accessor function at <offset>`, verbatim the `Demangling` `NodePrinter` fallback, so dump and interface spell the same honest text. Offline the reference is unresolvable by construction — the embedded thunk would have to be executed.
- Both paths additionally degrade to the bare case when a payload renders empty, so parentheses never close around nothing for any future uncovered `Node.Kind`.

## Bug Fixes

- **`SwiftPrinting`** — a specialized definition rendered unbound (header and field types) on the interface path.
- **`SwiftPrinting`** — kind-9 accessor-function references rendered as an empty string, emitting invalid Swift (`case type()`, `indirect case valueAttached()`, and a dangling `var _storage: `).
- **`SwiftDeclarationRendering`** — comment-rendering errors were swallowed, producing ghost blank indented lines instead of failing the type; the multi-payload enum descriptor lookup rescanned `__swift5_mpenum` per enum and let one bad descriptor take down the batch.
- **`SwiftPrinting`** — a `Void`-payload enum case collapsed to the bare form on the interface path while the dump path spelled it `case a()`.
- **`SwiftPrinting`** — an extension whose conformance clause failed to resolve dropped the clause silently instead of distinguishing "no protocol node" from "resolution threw".

## Compatibility

- No API removals or renames, and no snapshot `formatVersion` change (still 5). Default rendering is byte-identical to `0.14.0` except where a listed bug fix changes it.
- `--enum-layout-style` keeps its meaning, but now implies `--emit-enum-layout`. If you relied on passing the style with no emit flag to get *no* enum-layout comments, drop the style option.

## Testing and CI

- New `SwiftSectionCommandTests` — the repository's first CLI test target, testing the executable target directly via `@testable import` — pins template-name resolution, the three-layer precedence, implicit enabling, and the comment-kind OR merge.
- New `MultiPayloadEnumDescriptorCacheTests` and `EnumCaseRenderingParityTests`; `NestedFieldOffsetExpansionDepthLimitTests` now pins the live constant in `SwiftDeclarationRendering` instead of the deleted SwiftDump copy.
- The `SymbolTestsCore` fixture gains an `AccessorFunctionReferences` namespace (covering the always-noncopyable path, which is deployment-target-independent) and a `VoidPayloadEnumTest` enum. Snapshots normalize the rendered thunk offsets so they stay stable across fixture rebuilds.
- The macOS workflow splits debug and release into parallel matrix jobs, caches the per-configuration SwiftPM build directory (keyed on the post-update `Package.resolved` + `Package.swift`), passes `--enable-experimental-prebuilts` explicitly, and moves to Xcode 26.6.
