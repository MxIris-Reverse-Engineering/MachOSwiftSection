摘要

0106 让改了名的 C 导入类型在声明、成员类型和扩展头里一律写 Swift 名，但还剩两处混用。第一处：镜像里有 descriptor、Swift 名与 C 名相同的类型，声明行写裸名 struct AGDescriptionOption，引用和扩展头却写 __C::AGDescriptionOption。第二处：字段布局注释（展开的嵌套字段偏移树）用固定的 .default 选项印类型名，var base: AnyWeakAttribute 下面的注释写着 identifier (__C.AGAttribute)，也不带模块选择器和 any。

本提案让名字表把「没有 ABI 名」的 descriptor 也收进来——编译器只在两个名字不同时才写 ABI 名，所以这样的 descriptor 证明了 Swift 名就是 C 名——引用处因此写裸名；再让 interface 路径的布局注释经打印器自己的类型拼写印类型名，离线（MachOFile）与进程内（MachOImage）两条后端一起改，dump 不变。镜像里没有 descriptor 的类型照旧写 __C::，跨镜像查找另开提案。

动机里的复现

用户打 macOS 27.2 的 AttributeGraph（显示 C 导入类型、注册 SwiftInterfaceBuilderTypeNameProvider、模块选择器、展开字段偏移），同一个类型出现两种写法：struct AGDescriptionOption { 的扩展头是 extension __C::AGDescriptionOption: @retroactive Swift::RawRepresentable；var base: AnyWeakAttribute 下面的注释写 identifier (__C.AGAttribute)、rawValue (Swift.UInt32)，而整份输出开着模块选择器。用户确认只做二进制能证明的部分。

提议方案

1. 名字表收「没有 ABI 名」的条目

  • 不是相关实体、没有 ABI 名（含完全没有 import info）、且直接位于 __C / __C_Synthesized 下 → descriptor 的名字就是 Swift 名，收进表；
  • 有 ABI 名 → 照旧，trustsUserFacingName 采信才收；相关实体不收；import info 读不出来不收。
  • printType 不用改；声明行与 marksCImportedTypeNames 标注都不变；嵌在 C 类型里的类型不收。

2. 布局注释经打印器的拼写印类型名

  • NestedFieldOffset 与进程内缓存的行多存 typeNode；typeName 保持 .default，仍是防环键与 dump 的拼写。
  • 渲染配置加包级开关 spellsFieldLayoutTypeNamesThroughResolver 与异步方法 fieldLayoutTypeName(printedName:typeNode:)；interface 打印器打开，dump 不开。
  • 两条后端渲染树改成异步；树的形状、isLast、防环与深度判断、#log 告警不动。

于是注释的类型名与声明写法一致：.swiftName 下是 AnyAttribute，.cName 下是 __C.AGAttribute；开了模块选择器写 Swift::UInt32；存在类型带 any；语法糖（Swift.Int?）；私有类型不带判别符、局部类型只写名字——都和声明一样。

没有询问就采用的假设

  • 范围取字面最小：只补 0106 留下的两处，改名但不可信的类型不碰。
  • 「没有 ABI 名 = Swift 名就是 C 名」依据 IRGen 的 computeIdentity；唯一会错的是 C 名不带前缀、又被导入成成员的类型，没见过实例。
  • dump 不跟着改；进程内缓存存节点；开关放在渲染配置里，不按 DemangleResolver 的 case 判断。

非目标

  • 镜像里没有 descriptor 的类型（AGValueOptions、AGSubgraphRef）保留 __C::；跨镜像查找另开提案。
  • 改名但不可信的条目（TreeValue、Signature、ValueFlags）；@retroactive；dump 的任何输出与 diff / snapshot / evolution 的键；枚举布局等其它注释。

名字表与渲染配置的签名

解析失败或得到空串时退回 printedName，一行注释不会因此消失。名字表先按 import info 排除相关实体与不可信改名，再 demangle 进表的条目。

两条后端

离线：expandedFieldOffsets(for:baseOffset:) 与 renderNestedFieldOffsetTree(_:ancestors:) 改成 async，每行先 await configuration.fieldLayoutTypeName(…)，再套进 async 版 commentRegion 递归子行。

进程内：walkNestedExpandedFieldOffsets 改成 async；建层时 nestedTypeNode(for:parentMetadata:) 求一次节点，存进行里，typeName 由同一个节点 .default 印出，与改前派生相同。

调研

9 条前期调研
  1. 名字表原先只收改了名、可信的条目；printType 只在表里有答案、模块没解析出来时写裸名。
  2. 声明行本来就用 descriptor 的名字，同名类型的声明是裸名；扩展头经 typeDemangleResolver。
  3. IRGen computeIdentity 只在 Swift 名与 Clang 名不同时写 ABI 名。
  4. AttributeGraph：AGDescriptionOption 没有 ABI 名；AGTreeValue → TreeValue、AGTypeSignature → Signature 不可信；16 个只在签名里出现的类型在 AG 里没有 descriptor。
  5. 布局注释的类型名在离线与进程内都用 .default 印，也是防环键与 transformer 模板的输入。
  6. interface 路径的渲染配置拿着打印器的 typeDemangleResolver，这是唯一的构造点；打印器的节点身份缓存每次 printRoot 一份。
  7. OfflineSpecializationParityTests 要求两条路径逐字节相同，所以一起改。
  8. 进程内缓存存节点而不是渲染时重算：0067 去掉的正是重复 demangle。
  9. dump 的配置是 .options(…)，按 mangled 身份打印，不受影响。

替代方案

5 条被否的路径
  • 按 DemangleResolver 的 case 决定：.builder 不等于 interface 打印器。
  • dump 的注释也走它自己的解析器：会改 dump 快照，dump 没有拼写开关；记为后续项。
  • typeName 直接改成打印器拼写：SwiftLayout 拿不到打印器，且它是防环键。
  • 进程内渲染时重新 demangle：把 0067 去掉的成本带回来。
  • 同名类型也写 __C::：声明行不能带模块，二进制已经证明了 Swift 名。

影响

  • 源码兼容性：纯新增。NestedFieldOffset 多一个公开属性，init 多一个带默认值的参数；渲染配置的新成员是 package。ABI 兼容性不适用（SPM 源码分发）。
  • 输出：同名 C 类型的引用与扩展头少了 __C.（没开 --resolve-c-module-names 时 CGRect、CGPoint、RBColor 也是）；interface 的布局注释与声明同拼写。dump、diff 键、snapshot 不变。
  • 开销：SwiftUICore 打开展开字段偏移的 interface 从 7.10 秒到 7.39 秒（+4%）；进程内缓存 SwiftUICore 全部展开后多占约 2.1 MB（A91）。
  • RuntimeViewer：内容区文本跟着变，Imported Type Names 切到 C 名时注释也写 C 名；transformer 模板收到打印器拼写；不需要改代码。

落地步骤

  1. 名字表收同名条目（已完成）：同名 C 类型的引用与扩展头写裸名；解析器找到模块时写 模块.名字；C 名模式照旧；不可信改名照旧；不收嵌套的匿名结构；声明名不带标注。
  2. 离线路径的布局注释经打印器拼写（已完成）：改名与同名的 C 类型写声明用的名字；C 名模式写 C 名；模块选择器写 ::；dump 仍是 .default。
  3. 进程内路径的布局注释经打印器拼写（已完成）：进程内同样写 Swift 名与模块选择器；对非泛型字段两条路径逐行相同；带缓存与不带缓存逐字相同（开关关着与开着）。
  4. 文档（已完成）。

后续项

  • 跨镜像查找 C 类型的 Swift 名（AGSubgraphRef → Subgraph），另开提案。
  • dump 的布局注释是否也走 dump 自己的解析器；@retroactive 按 mangling 的 __C 判定。
  • OpaqueReferenceSpelling 同样用 .default 印类型名；opaque 类型的注释行与声明仍不一致。
  • 0106 的疑似遗留：NS_ERROR_ENUM 的 Code 枚举被当成可信的顶层改名（未实测）。
  • pack、整数泛型参数、关联类型成员的嵌套行两条路径对照未覆盖；位置命名的局部类型两条路径地址不同。
  • 符号索引的建索引死锁（next 上就有）：同一镜像 15 个以上调用方并发建索引时占满 16 个大栈线程，持锁者的 DemanglingWave 分不到线程。
  • 顶层 C++ 类模板特化的引用从 __C.Box<CInt> 变成 Box<CInt>，留给 C++ interop 的提案。
