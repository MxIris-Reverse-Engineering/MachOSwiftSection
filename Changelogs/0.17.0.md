# 0.17.0

A feature release on top of `0.16.0`, aimed almost entirely at one question: **how much of the original Swift source can be honestly recovered from a stripped binary, and how clearly can the output say when it cannot?** Six evolution proposals land ([0006](../Documentations/Evolutions/0006-final-keyword-and-lazy-accessor-type-recovery.md)–[0011](../Documentations/Evolutions/0011-opaque-primary-associated-type-attribution.md)) plus two more that were still `draft` at landing time, most of them driven by [issue #106](https://github.com/MxIris-Reverse-Engineering/MachOSwiftSection/issues/106) — a report from someone rebuilding a compilable `.swiftinterface` for Xcode's private `SourceEditor.framework` by hand, which is the sharpest test this output has had.

1. **`final` is recovered on class members** (proposal 0006). A member with no vtable method descriptor was declared `final` in source — the same ABI fact that already backs `class` / `static` recovery, read the other way. This was the only **link-breaking** gap in the previous output: a member reached through a dispatch thunk must be declared plainly and one with a direct symbol must be declared `final`, and getting it backwards fails the link outright. The same change stops lazy `var`s printing their `Optional` storage type instead of the type callers see.
2. **Extension blocks stop being emitted several times over** (proposal 0007). Containers are now unified at index time, one per (target, protocol, `where` fingerprint, `@retroactive`), so `printRoot`, per-type printing, and diffing all benefit. Members resolved through a protocol requirement's *default* implementation are labelled `// protocol-extension default` instead of masquerading as the type's own API.
3. **A header block and export-status annotations** (proposal 0008), both off by default. `--emit-header` prints install name, UUID, architecture, file type, generator, a library-evolution detection line, and a short digest of facts the binary provably cannot carry. `--emit-export-status` marks members whose symbols — *including* their `Tj`/`Tq`/`Tu` derived forms — have no export-trie entry, with `override` and `@objc` members exempt because they are reachable without an exported symbol of their own.
4. **`TypeIndexing` ships as a library product** (proposals 0009 + 0010), resolving `__C.NSString` to `Foundation.NSString`. The target had been commented out of `Package.swift` since the Swift 6 migration; what kept it unusable was an hour-scale first index, now split into cheap file discovery plus per-module interface generation *after* dependency filtering, cached per exact SDK build (≈33 s first run on the fixture's dependency set, ≈10 s cached). SwiftSyntax is deliberately **not** a runtime dependency — type names come from sourcekitd's structured response. `--resolve-c-module-names` enables it; `--supplementary-apinotes` accepts user-provided `.apinotes` mappings for frameworks with no SDK module at all (AttributeGraph), for which no tool can recover the spelling on its own.
5. **Opaque return types attribute their primary associated types per protocol** (proposal 0011). Same-type constraints were distributed to *every* protocol in a composition, producing illegal Swift like `some Swift.Equatable<[A]>` — `Equatable` has no associated type. The constraint's anchor protocol is in the mangling all along and the demangler keeps it; only the provider was discarding it. When the anchor cannot be resolved, nothing is attached rather than something wrong.
6. **`swift-section evolution --interface`** renders an N-version ABI lineage as a single **annotated union interface**: every declaration that ever existed appears once, unchanged ones bare, changed ones carrying `// [●●○] removed in 26.0`-style presence bitmaps and event phrases. Every input must be a binary or dyld shared cache in this mode; snapshot JSON is rejected. Annotation facts come only from `ABIEvolution`, so the interface view, the lineage report and the JSON can never disagree.
7. **Two externally reported bugs are fixed.** [#115](https://github.com/MxIris-Reverse-Engineering/MachOSwiftSection/issues/115): `dump` cross-contaminated the members of same-named private types (SwiftUI's two `ArchivableDisplayList`s), because the member index's string key is printed *without* private discriminators and the dump path queried by name alone — present since `0.14.0`. [#116](https://github.com/MxIris-Reverse-Engineering/MachOSwiftSection/issues/116): `0.16.0`'s foreign-struct guard degraded every field of a `#pragma pack` C struct (`__C.CMTime`) whose offsets were in fact correct; the guard now admits offsets **proven** by tight packing.
8. **The `diff` and `evolution` interface renderers share one structure walker.** They were the same traversal written twice (two stretches byte-identical, the two matching algorithms N=2 special cases of each other); each is now a thin emission strategy over `InterfaceUnionWalker`, net −256 lines. The `diff` path's double-indented accessor blocks disappeared with the merge. Public API is unchanged.
9. **Four build environment switches are gone** — `MACHO_SWIFT_SECTION_USE_SPM_PREBUILD_VERSION`, `USE_CUSTOM_MACHOKIT`, `USE_CUSTOM_OBJC_SECTION`, `MACHO_SWIFT_SECTION_USE_SWIFTTUI`. The dependency set they selected between no longer exists.

Everything that *adds* information to the output is behind a flag defaulting to off (items 3 and 4, and item 2's `// protocol-extension default` label, which rides on `--emit-member-addresses`). Default `dump` / `interface` output changes only where items 1, 2, 5 and 7 correct it — a recovered `final`, one extension block instead of three, legal Swift for opaque returns, and members attributed to the right same-named private type. `diff --interface` additionally loses the doubled indentation on accessor blocks (item 8).

## Compatibility

**Breaking source changes:**

| Before | After |
|---|---|
| `TypeNameResolvable.swiftName(forCName:)` (`SwiftPrinting`) | `swiftName(forCName:category:)`, taking a `CImportedTypeNameCategory`. A category-blind lookup rewrote *class* references with the *protocol*'s rename — ObjC lets a class and a protocol share one C name (`NSObject`), and APINotes renames only the protocol (`NSObjectProtocol`). The protocol has a default implementation, so a conformer left on the old spelling **silently stops being called** rather than failing to compile |
| The four build environment switches above | Removed; no replacement |

**Additions:**

- **`TypeIndexing` library product**, whose whole consumer-facing surface is one type: `SwiftInterfaceBuilderTypeNameProvider`, an extra-data provider you attach to `SwiftInterfaceBuilder`. Everything behind it (`TypeDatabase`, `APINotesIndex`, `ModuleInterfaceIndexer`, the supplementary-APINotes loader) is `package`-scoped on purpose — the pipeline's shape is not a contract yet. macOS-only (every source file is `#if os(macOS)`); the provider requires `macOS 13.0` and returns `nil` for a binary with no build-version load command mapping to a known SDK platform.
- **`SwiftInterface`** — `SwiftEvolutionInterfaceBuilder<each MachO>` (compile-time arity, pack-generic) and `AnySwiftEvolutionInterfaceBuilder` (runtime arity, what the CLI uses), plus `EvolutionLine`, `EvolutionAnnotation` and `SwiftEvolutionInterfaceBuilderError`. The opaque-attribution and shared-walker machinery is internal. `SwiftDiffableInterfaceRenderer<OldMachO, NewMachO>` is retained as a shell that erases into the shared walker.
- **`SwiftPrinting`** — `InterfaceHeaderInfo` / `InterfaceHeaderBlock` (public so a host bypassing `printRoot` can render them), `CImportedTypeNameCategory`, and the two print-configuration flags behind `--emit-header` / `--emit-export-status`.
- **`SwiftDeclaration`** — `isFinal` and `isProtocolExtensionDefault` on `FunctionDefinition` / `VariableDefinition` / `SubscriptDefinition`; `accessors`, `accessorTypeNode`, `isFinal` and an `AccessorRepresentable` conformance on `FieldDefinition`. All defaulted, so existing memberwise-init callers still compile.
- **`MachOSymbols`**, on the `@_spi(Internals)` / `@_spi(ForSymbolViewer)` `SymbolIndexStore` — `isExported(name:in:)` / `isExportedIncludingDerivedSymbols(name:in:)` / `containsSymbol(named:in:)` / `symbolCount(of:in:)`, and `node:`-taking overloads of `methodDescriptorMemberSymbols`, `thunkAttributeMembers` and `typeInfo(for:)`. The name-only overloads remain, now documented as deliberately *aggregating* semantics — querying with a node is what separates same-named private types.
- **CLI** — `--emit-header`, `--emit-export-status` (`dump` and `interface`), `--resolve-c-module-names`, `--supplementary-apinotes` (`interface`), `--interface` (`evolution`).

**New package dependencies**, both used only by `TypeIndexing` and both carrying a macOS platform condition:

- `SourceKitD` → `from: "0.1.0"`
- `swift-apinotes` → `from: "0.1.0"`

**Pinned dependencies** are otherwise unchanged from `0.16.0`: `swift-demangling` `0.6.0 ..< 0.7.0`, `MachOObjCSection` `0.8.105 ..< 0.9.0`, `MachOKit` `0.52.101 ..< 0.53.0`, `MachOKitExtensions` `from: "0.1.1"`, `swift-semantic-string` `from: "0.3.0"`.

No snapshot `formatVersion` change.

## Testing

Full suite green at **1,557 tests / 293 suites** (`--skip IntegrationTests`), up from 1,433 in `0.16.0`. Both externally reported bugs ship with regression tests that fail on the previous commit, and the fixture project gains `PrivateDoppelgangers` (same-named private type and protocol pairs) and `ForeignPackedTime` (a `#pragma pack(4)` C struct) to pin them.
