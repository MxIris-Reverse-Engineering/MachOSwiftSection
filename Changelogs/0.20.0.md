# 0.20.0

A minor release on top of `0.19.0`. `dump` and `interface` now read the types Swift hides behind accessor functions without running any code, and recover the `@objc`, `override`, `@objc @implementation` and property-wrapper spellings that stripped OS frameworks no longer carry. objc-section's commands ship inside `swift-section` as `swift-section objc`. Several rendered names change on purpose; see Compatibility before upgrading ABI baselines.

## What's new

- **Types behind accessor functions are read offline.** A field or associated type whose metadata sits behind an accessor function (availability-conditional `some View`, noncopyable payloads) used to print as `accessor function at 0x…`. `dump` and `interface` now decode the accessor's ARM64 code and print the type, with its availability branches as a comment — in macOS, iOS-device and simulator dyld caches and in standalone files.
- **`--dependency-search-path`** (`dump`, `interface`, `snapshot`, repeatable) — where a standalone binary's dependencies live: a Mach-O file, a dyld shared cache file, or a directory used as a system root (a simulator runtime's `RuntimeRoot`). Without it, paths are inferred from where the binary sits and the running system's cache is used; an iOS binary read on a macOS host needs its runtime named here.
- **`swift-section objc`** — `dump`, `interface`, `snapshot`, `diff` and `evolution` for Objective-C, moved from `objc-section` with the same output: `objc-section <command> …` becomes `swift-section objc <command> …`. The standalone `objc-section` is being retired after this release.
- **`@objc` members are recovered from the ObjC method table**, even where an OS framework stripped the thunk symbols: `@objc`, `@objc(selector:)` where the selector is not the one the compiler would derive, and `override` of members an ObjC ancestor implements — that chain is followed into the binary's dependencies.
- **`@objc @implementation` classes** print as `@objc @implementation extension X` with their stored properties; `dump` gains an `objcImplementationClasses` section.
- **`--infer-objc-overrides`** (`interface`, off by default) — also marks as `override` a method tied to a member by its selector's name alone. `dump` always shows these ties, marked `(selector name, no symbol evidence)`.
- **Property wrappers**: `interface` prints `@Wrapper var x` and hides the compiler-synthesized `_x` / `$x`, for wrappers from other images and for stripped declarations too.
- **Swift 6.4 binaries**: `Builtin.Borrow` metadata is read and laid out statically; a `@_rawLayout` type's artificial storage field is laid out, and hidden from `interface`, which prints `@_rawLayout(size:alignment:)` where only a builtin descriptor survives. An actor's `$defaultActor` storage is no longer printed in `interface`.
- **Private types in dyld caches keep their private discriminator**: `dump` prints `(Name in _…)` as it already did for binaries that keep their symbols, and two same-named private types no longer merge into one in `interface`.
- **Library**: models for key path components and property descriptors, async and coroutine function pointers, accessible functions (`__swift5_acfuncs`), capture descriptors (`__swift5_capture`), generic metadata patterns and function type metadata's trailing objects; type and protocol definitions know whether the image exports them; `NestedFieldOffset.byteWidth`, a nested field's proven value size; new library product `SwiftThunkAnalysis`.

## Fixes

- `dump` and `interface` crashed about one run in five on a dylib whose module declares no class (no `__DATA` segment) — including the dylib Homebrew's formula test builds. Present in `0.19.0`; fixed by MachOKit `0.52.103`.
- `interface` printed nothing for several node kinds in type positions — in SwiftUI, 201 `Predicate<>`, 8 bare `-> ` and 122 `init<>()`.
- A type declared in another module's extension lost the extended type: `Invalidations.Tuple` for `NSView.Invalidations.Tuple`.
- Specialized generic names that come from the runtime printed `(unknown context at $…)`, or dropped a private type argument's module and enclosing types.
- Opaque result types: an unresolvable reference printed the conforming type itself and now prints the legal `@_opaqueReturnTypeOf(…)` spelling; `some Base & P` kept only `P`; generic arguments inside a constraint were dropped (`some Sequence<Set<Int>>` lost its `<Int>`).
- `interface --parse-opaque-return-type` (and RuntimeViewer's export) crashed with `Index out of range` on an opaque parameter that carries no runtime-visible constraint, seen on PhotosUIFoundation.
- A conformance to a `private` protocol had no type highlighting and no link in semantic output such as RuntimeViewer's.
- A method whose implementation pointer is null no longer drops its whole type from the index.
- A malformed symbol whose value is not an offset no longer crashes the process while an image is indexed.

## Breaking

Source level — this package is distributed as source, so every downstream recompiles:

- `MetadataReader` → `SymbolicDemangler` (SPI `Internals`). The old name remains as a deprecated alias for one release.
- `PrimitiveTypeMapping` and `PrimitiveTypeMappingCache` are removed; C-imported type names now come from each descriptor's own import info.
- `FieldLayoutRenderable` no longer refines `MachOSwiftSectionRepresentableWithCache`. Where a generic constraint needs both, write `MachOFieldLayoutRenderable`.
- `HeapLocalVariableMetadata.captureDescription` points at a `CaptureDescriptor` (was `String?`).
- `numUnderlyingTypeArugments` → `numUnderlyingTypeArguments`. The misspelling remains as a deprecated forward for one release.

## Compatibility

- **Rendered names change** in four deliberate places: types behind accessor functions (now read), private types in dyld caches (`dump` now shows their discriminators), C-imported type names (now follow each descriptor's import info, as the runtime does), and types declared in another module's extension. Anything keyed on these names changes with them — an ABI snapshot saved by `0.19.0` reports the affected types as removed and re-added, so regenerate baselines with `0.20.0`. Snapshot `formatVersion` is unchanged (5).
- **New dependency**: swift-capstone `6.0.0 ..< 7.0.0`, with only its `AARCH64` trait enabled; it is C source and builds for any host architecture.
- **Dependency floors**: MachOKit `0.52.103 ..< 0.53.0` (was `0.52.101`), swift-demangling `0.7.1 ..< 0.8.0` (was `0.6.3 ..< 0.7.0`), MachOObjCSection `0.8.106 ..< 0.9.0` (was `0.8.105`). All other pins are unchanged from `0.19.0`.
- The recoveries above are on by default; only the name-only override inference waits for `--infer-objc-overrides`.

## Requirements

- Swift 6.2+
- Xcode 26.0+
