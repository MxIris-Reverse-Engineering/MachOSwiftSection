摘要

Tests/IntegrationTests/ 里维护者手检的输出有三类：单版本接口、两版本 diff、N 版本演进。演进一类在 0110 里已合并成「一个套件声明一次镜像、dump(.kind, to: .file / .console) 一行一个测试、Swift 与 ObjC 都出」；另两类还是各写各的：diff 自带三个「新旧两版」基类，读 cache 只开主文件，和演进套件、CLI 都不一样；接口套件为了多开一个选项把整份配置抄一遍；两类都只出 Swift。

本提案把三类放进同一个目录 Tests/IntegrationTests/InspectionDumps/，共用一套骨架：公共协议 InspectionDumpTests；diff 与演进共用版本轴（diff 就是只有两个版本的轴，cache 对改为整份打开）；每类一个「输出种类」枚举加一个 dump 入口；AppKit 的接口套件多出整镜像 ObjC 头文件，AppKit 的 diff 套件多出 ObjC 变更列表与 JSON，Swift diff 报告也多写一份 JSON。

测试从 20 个（接口 10、diff 10）变成 38 个（接口 14、diff 24），演进的 43 个不变。只动 IntegrationTests 与它在 Package.swift 里的依赖表，不碰库代码。

要你定

实现完成，待看过后收尾。以下是没问用户就采用的假设：

  1. ObjC 输出只加在 AppKit 的四个套件上；别的套件要看 ObjC，加一对一行测试即可。
  2. ObjC 头文件开满注释（ivar 偏移、属性特性、方法 IMP 地址、访问器地址），与 Swift 接口开满字段偏移、成员地址对齐。
  3. Swift diff 报告多写 -Diff.json；变更列表照旧用两个 builder 的 abiModule()，不改成快照往返。
  4. 套件类名保留（DyldCacheTests、MachOFileTests……），只改外层枚举名与测试函数名；旧测试名不留别名。
  5. Xcode 的 diff 对改为按版本号（"26.3.0" / "26.4.0"）取，版本号也当轴标签。
  6. diff 轴不足两个版本时打印一行说明、不写文件。

采用的假设

  • diff 的 cache 对改为整份打开（用户在澄清时选定）；输出可能与现状有出入，以与 CLI 一致为准。
  • 控制台只打印一份：diff 的 swiftInterface 写文件时出 inline 与 unified，打到控制台只出 inline，并只在写文件时渲染 unified。
  • 维护者在公司那台 next 检出里未提交的接口套件实验不碰（用户在澄清时选定）；合回那个检出前由维护者自己收掉，否则合并会被挡住。实验里的「改读 AttributeGraph」在新结构里是给 InterfaceTestSuite.DyldCacheTests 改 cacheImageName。
  • 其余假设见「要你定」。

非目标

  • 不动 SwiftDump/ 的 DumpableTests 一族、RenderingVerificationTests、SwiftInterfaceIndexerTests。
  • 不给 diff 加镜像组：两个 differ 都没有镜像组入口。
  • 不改库代码、不改 CLI；不运行 IntegrationTests。

详细设计

InspectionDumpTests.swift 与 VersionAxis.swift
  • DumpFile { suffix, fileExtension, text }、DumpOutput { consoleText, files }；deliver(_:to:writingFile:) 打印 consoleText 或把每个文件交给调用方的命名函数（接口按 write(_:for: machO…)，diff 与演进按 write(_:forImageGroup: newest.images…)）。
  • preparedObjCIndexer(of:) 改成对 ObjCMetadataSource & MachORepresentableWithCache 泛型，进程内镜像也能用。
  • VersionAxes 存两个 let（Swift 轴、ObjC 轴）加 switch；三个轴基类都 @TestActor、都在 init 里建好它、都实现 nonisolated func versionAxis(for:)。
  • MultiVersionDyldCacheImageTests 的类属性与取镜像逻辑原样保留。CrossVersionMachOFileTests 加 oldVersionLabel / newVersionLabel（默认 "18.5" / "26.5"），镜像名取 imagePath.lastPathComponent。CrossVersionXcodeFrameworkTests 用 oldXcodeVersion / newXcodeVersion 拼 /Applications/Xcode-<版本>.app/…。
  • objcSnapshotDocument(of:label:) 从演进管线搬到 VersionAxisDumpTests 的扩展里，diff 的 ObjC 报告也用它。
InterfaceDumpTests.swift
  • dump<MachO: MachOFieldLayoutRenderable & ObjCMetadataSource>(_ kind:, of machO:, to:)。
  • 后缀按 machO.asMachOImage != nil 取 ImageDump 或 FileDump，ObjC 前加 ObjC、扩展名 h。
  • swiftInterface：与现状逐字相同的配置，只把 printExportedDeclarationsOnly 换成协议属性。
  • objcInterface：ObjCInterfaceBuilder(indexer:machO:)，按 classes、protocols、categories、structs、unions 的顺序、名字排序逐个取接口，每段后接空行，与 objc dump --file 一致。
  • 在 @MainActor 的基类上改 printsExportedDeclarationsOnly 要写 nonisolated var；XcodeMachOFileTests 的基类不隔离。
DiffDumpTests.swift
  • 取 versionAxis(for: kind.language) 的第一个与最后一个版本；不足两个时打印 No diff: … version(s) carry … metadata 后返回。
  • swiftReport：两个 SwiftDiffableInterfaceBuilder 在一个 measuringPreparation 里准备；ABIDiffer + ABIDiffReporter + 结论行；JSON 用 ABIJSON.encoder()。
  • swiftInterface：SwiftDiffableInterfaceRenderer(old:new:).printAnnotatedInterface(format:)，inline 必出，unified（.unified()）只在写文件时渲染。
  • objcReport：两边 objcSnapshotDocument，ObjCAPIDiffer + ObjCAPIDiffReporter + API-breaking: … · backward-compatible: …；JSON 用 ObjCAPIJSON.encoder()。

动机

  1. diff 自带三个「新旧两版」基类，和演进的版本轴是同一件事的两种写法；演进的模拟器套件还得借 diff 的基类、自己拼轴。
  2. diff 读 cache 只开主文件，演进与 CLI 整份打开：同一个 AppKit 经两条读路径。
  3. diff 的 DyldCacheTests 注释写 SwiftUI、15.5 → current，实际读 AppKit、26.5.1 → 27.0。
  4. 接口的 XcodeMachOFileTests 为开一个选项抄了整份配置。
  5. 接口套件用 machO is MachOImage 判读取器，项目规则要求问 asMachOImage。
  6. 只有演进出 ObjC；AppKit 的 ObjC 部分远大于 Swift。
  7. indexConfiguration 在三处各写一份。

调研

  • CLI 管线：objc dump 按五种声明、名字排序拼接（ObjCDumpRequest.swift、ObjCInterfaceSession.swift）；diff / --json / --interface（ABIDiffRequest.swift:67-150）；objc diff 只有变更列表与 JSON，没有带标注的头文件（ObjCAPIRequests.swift:56-108）。
  • 锁定的 MachOObjCSection 0.8.209 上，用到的 ObjC 接口都在，MachOImage 与 MachOFile 都遵循 ObjCMetadataSource；ObjCGenerationOptions 在 ObjCDeclarationRendering，需要加依赖；Tuist/Package.swift 不用改。
  • 单镜像时 write(_:for:) 与 write(_:forImageGroup:) 文件名逐字相同，diff 改用轴后文件名不变。
  • IntegrationTests 外只有 ABIEvolutionDesign.md:235 写着现行路径；别处的旧套件名是历史记录。

替代方案

  • 单版本接口也走版本轴：放弃。接口要读进程内 MachOImage，轴与演进构建器只收 MachOFile。
  • 三类合成一个枚举、一个协议：放弃。三类输入形状不同，分开后编译期就排除了「对单个镜像跑 diff」。
  • diff 保留自己的基类、只改结构不加 ObjC：用户在澄清时否掉。
  • ObjC 加在每个套件上：暂不，需要时加一对一行测试即可。
  • 套件按镜像改名：放弃。接口与 diff 套件是维护者临时指向别的镜像的探针，按镜像命名容易名不副实。

影响

  • 纯测试改动，没有公开 API 变化；IntegrationTests 不是 product。
  • Package.swift 只为 IntegrationTests 多列一个已有的 MachOObjCSection product；下游仓库无影响。
  • 维护者手动运行时用的测试名会变。

落地步骤

验证在 Ultra 上做：queued-build swift build --build-tests，默认 Xcode 与 Xcode 26.6 各编一遍；不运行 IntegrationTests。

  1. 公共骨架与版本轴（已完成）：新目录，四个文件移入并改名；两个旧文件只做机械改名以保持能编。
  2. 接口一类（已完成）：InterfaceDumpTests.swift、InterfaceTests.swift；删旧接口文件；Package.swift 加依赖。
  3. diff 一类（已完成）：DiffDumpTests.swift、DiffTests.swift；删旧 diff 文件。
  4. 文档（已完成）：ABIEvolutionDesign.md、账本、索引；维护者可选地挑几个 file 测试前后比对。
